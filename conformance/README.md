# Conformance fixtures

This directory organizes independent evidence for parser, document-metadata,
and rendering conformance. Imported corpora include
[rmscene's 13 parser fixtures](parser/rmscene/README.md),
[four metadata bundles](metadata/remarquee/README.md),
[two pencil-thumbnail pairs](rendering/tablet-thumbnails/eink-sync/README.md), and
[one official-export pair](rendering/tablet-exports/remarkable-rm/sample-page/README.md).
Existing crate-local fixtures remain in place.

Parser, metadata, pencil appearance and ink-geometry comparisons, and comparison
controls run in the normal Rust test suite. The two pencil appearance tests now
pass with unchanged thresholds. The official-export pair is quarantined as an
invalid full-image oracle: the PNG and binary contain different page content
(see its README for independent verification). It remains one ignored diagnostic
with CI image artifacts, pending a matching source/export pair.

## Layout

```text
conformance/
├── parser/                       # .rm inputs and expected parsed semantics
├── metadata/                     # Complete document bundles and page mappings
└── rendering/
    ├── tablet-exports/           # Inputs paired with official PNG/PDF/SVG exports
    ├── tablet-thumbnails/        # Inputs paired with lower-resolution previews
    └── third-party/              # Inputs paired with another renderer's goldens
```

Within each category, group cases as `<source-project>/<case-id>/`. Keep each
case's inputs, expected results, and provenance together. If several categories
use the same input, reference its existing path rather than copying it.

## Attribution and provenance for imported cases

Each imported case must include a `README.md` recording:

- Original project, author or contributor credit, source URL, exact commit, and
  original paths (or issue attachment URLs).
- SHA-256 hashes of original inputs and reference files; record any extraction,
  renaming, conversion, or other modification separately.
- Applicable fixture license or permission and the original copyright/license
  notices. Preserve those notices alongside imported material. Do not assume a
  repository's code license automatically covers every attachment or document.
- Device model, firmware, orientation, template, and capture date where known;
  explicitly mark unknown values.
- How expected values were established. For images, identify tablet export,
  tablet thumbnail, or third-party renderer, including renderer version and
  rasterization settings where applicable.
- The edge case exercised, expected result, and any known unsupported behavior.

Third-party fixtures retain their own terms; the repository's MIT/Apache-2.0
license declaration does not relicense them. Sources without established reuse
terms remain links in this catalog until permission is established.

## Validation principles

- Assert parsed semantics independently of this project's current output.
- Test metadata using document context: ordered live pages, PDF redirection,
  templates, deleted pages, and absent annotation files.
- Keep reference origin explicit. A third-party golden can expose differences,
  but can also preserve that renderer's errors.
- Normalize image dimensions, crop, background, and rasterization settings before
  comparing. Measure ink-region differences so white margins cannot hide a
  missing stroke; retain expected, actual, and difference images on failure.
- Record unsupported cases explicitly rather than regenerating references to
  match current behavior. Reference updates require a documented reason.
